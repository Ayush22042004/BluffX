# v0.3.0 existing-mailbox Gmail API delivery

Date: 2026-11-15. Local implementation; not deployed. Version remains 0.3.0.

Added Gmail HTTPS API delivery from an existing Gmail/Workspace mailbox, without SMTP or a custom sending domain. Existing verification/reset/deletion/report flows reuse the shared backend mailer. Separate Gmail OAuth credentials avoid changing player Google sign-in. Setup is owner-only; recipients do not authorize Gmail access.

New `gmail-api.js` composes RFC email using the existing Nodemailer MIME composer, refreshes/caches access tokens with concurrent refresh sharing, validates the configured sender, uses bounded HTTPS calls and sanitizes errors. No SMTP transport or new dependency. Gmail reports declare a zero automatic retry window because Gmail send has no provider-idempotency guarantee; uncertain mail is retained for review rather than resent across restart/provider changes.

New `gmail:authorize` helper runs only on localhost port 4055, requests send-only Gmail plus basic identity scopes, checks state/PKCE and the signed sender identity, and writes the token to an ignored private file. Production uses environment credentials; no local-disk persistence is assumed. The helper prints no credential, sends no email and does not overwrite `.env`.

Updated mailer/provider selection, email-check CLI, environment template, Render blueprint and private report provider-change handling. New backend variables: `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`, `GMAIL_USER`, `GMAIL_REFRESH_TOKEN`; explicit `MAIL_PROVIDER=gmail`. No database migration or frontend secret. See [complete setup](../gmail.md), including Google's seven-day testing-token limitation and applicable verification requirements.

Tests cover MIME/HTTPS payloads, concurrent refresh caching, invalid senders, missing configuration and sanitized failures. Final verification results are appended after completion. Live owner authorization, account policy approval and inbox delivery remain pending; no production deployment or real email is claimed.

Verification: `npm test` passed 107 tests, with six opt-in database suites skipped and zero failures. Lint and release checks passed. A dry Gmail configuration check reported the OAuth client missing and sent no message. Gmail authorization cannot proceed until the owner configures the OAuth client and grants consent; a live success is not inferred from simulated tests.
