# v0.3.0 follow-up - visible social access and Player Codes

Date: 2026-11-13. Package version remains `0.3.0`. Local implementation; not deployed.

## Implemented

- Moved Friends, Records, Settings, Support and Privacy out of the footer into a persistent desktop side rail. Narrow screens show these controls near the top in a sticky row.
- Friends and Records open a right-hand drawer. The drawer supports Escape, keyboard focus containment and focus restoration. Main layouts reserve space for the desktop rail; crowded ten-seat layouts switch to the compact opponent grid sooner.
- Each signed-in account displays its player name and stable, unique **Player Code**, including a copy control in the profile sidebar and an identity card in Friends/Requests. The existing database-unique random identifiers are reused, not regenerated or migrated.
- Codes display as four uppercase groups, such as `ABCD-1234-EF56-7890`. Search and request authorization normalize uppercase/lowercase, spaces and hyphens to the existing canonical code.
- Added a dedicated Requests tab for incoming/outgoing requests, showing both names and codes. Search results distinguish existing friends and pending requests instead of offering duplicate sends. Accepted requests appear in Friends.
- Initial pending-request/invitation counts and existing targeted socket notifications drive the social indicator. Account-card reads happen on account load and meaningful social updates; no recurring polling was introduced.
- Guests receive a sign-in explanation. Unverified accounts can view their own code; email verification remains required for social interactions. Names may repeat, but the unique Player Code distinguishes accounts. A public code is not a password or login credential.
- Added a protected `/auth/social/card` endpoint returning only the current account's public name/code and incoming counts. Email addresses, internal account IDs, sessions and resume credentials are not exposed. Existing blocking, rate limits, privacy and invitation safeguards remain.
- Prevented the fullscreen hint from overlapping modal controls and aligned the drawer's privacy checkboxes. The existing fullscreen recommendation and compact beta version label remain.
