# v0.3.0 — Public privacy policy

2026-11-27. Added a standalone HTML privacy policy at `/privacy` and `/privacy/`, with canonical URL `https://bluffx.vercel.app/privacy`. It is readable without JavaScript, authentication, microphone permission or a backend connection. Explicit Vercel rewrites precede the SPA fallback. The login page and existing in-game Privacy information link to the same policy.

Content follows the inspected implementation: account/profile information, Google sign-in, owner-only Gmail sending authorization, social and gameplay records, reports, browser storage, optional unrecorded WebRTC audio, actual hosting providers, retention/cleanup behavior, email copies, security, contact and account deletion. The policy differentiates player sign-in from operator Gmail send access and describes Google API Limited Use. Contact uses the existing BluffX team mailbox. No legal approval or successful Google verification is claimed.

Files: `client/public/privacy/index.html`, `client/vercel.json`, `client/src/auth.jsx`, `client/src/LaunchTools.jsx`, `client/tests/privacy.spec.js`, root README and version index/this record. No database migration, new environment variable, provider or infrastructure is required.

Production build and lint passed. Six existing production-build browser account/report/deletion regressions passed. Both privacy browser tests passed after correcting the login link to use the static directory's trailing slash (the first run exposed a production-preview SPA fallback for the slashless link). Tests verify JavaScript-disabled access, zero backend requests, content/contact, mobile overflow and login navigation. The 390 × 844 mobile screenshot was visually inspected. Vercel explicitly supports both URL forms.

## CI development-route correction — 2026-11-27

The subsequent default CI browser run exposed a separate Vite development-server behavior: `/privacy/` returned HTTP 200 with the game's `BluffX` title, while `/privacy/index.html` served the correct policy. Earlier qualification used production preview and did not catch that development fallback. The fix adds a small middleware plugin in `client/vite.config.js` that maps `/privacy` and `/privacy/` (including query strings) to the static HTML before SPA fallback in both development and preview. Vercel's explicit production rewrites remain unchanged.

`client/tests/privacy.spec.js` now checks all URL forms return the policy HTML, in addition to JavaScript-disabled/mobile and login-link checks. `.github/workflows/verify.yml` also runs the privacy tests in its production-build stage, so CI checks both modes. Verification: `npm run test:e2e` passed 46 with 4 intentional skips, including all three privacy tests; the production-build auth/runtime/privacy stage passed all 7 tests. Lint, build, release/migration integrity and whitespace checks passed. These are local results matching CI commands; the hosted CI rerun is separate.
