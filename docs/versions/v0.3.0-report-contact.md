# v0.3.0 — Reporter contact details

Implemented locally on 2026-11-15; not deployed.

Manual support report emails now include the signed-in account's player name, stable Player Code and contact email, with email verification status. Identity comes from the authenticated server session and stored social profile, never from report payload fields supplied by the browser. If necessary, the existing social-profile creation mechanism allocates the account's persistent code inside the report transaction.

Contact details are frozen into the private email outbox with the report. They are not added to report acknowledgements, room broadcasts or public endpoints. Guests and previously queued messages without identity show unavailable contact details. Existing queued emails are not rewritten. Automatic diagnostic reports remain excluded from email forwarding.

The report form and privacy information disclose the contact details forwarded to support. No migration or new environment variable is needed. Restart the backend to load the change; deploy the frontend to show the updated disclosure. No production deployment or live test email was performed for this update.

Verification: five focused tests passed (`node --test server/test/report-email.test.js server/test/launch-http.test.js`), including forged identity rejection, stable account code, verified/unverified email labels and guest fallback. `npm run lint` and `npm run build` passed.
