# v0.3.0 — Personal records and mobile connection hotfix

Date: 2026-11-15. Branch: `fix/records-mobile`. Prepared separately from the pending party feature. Production still serves `4139f1f` until this hotfix is migrated and deployed.

## Findings

A read-only investigation of the intended production database confirmed that reported casual victories were saved in `bx_results` and visible in history. `bx_player_stats.games` and `wins` intentionally count competitive ranked results only, while the production beta uses `PLAYTEST_UNRANKED=true`. The UI labeled those fields simply "Games played" and "Games won", incorrectly suggesting casual games were lost. Challenge counts already included casual matches, adding to the confusion.

The mobile report did not contain a transport disconnect reason, and its table context could not be verified. It is not proof of one specific device failure. Inspection did reveal an aggressive four-second ping interval and four-second timeout, plus a page-restore path that reconnected only when `pageshow.persisted` was true. Those are addressed as concrete reliability hazards; no claim is made that every phone/network failure has been reproduced.

## Record correction

- Migration `008_personal_record_totals.sql` adds a durable `unranked_wins` counter and backfills existing casual victories from authoritative saved results. It does not change ranked games, ranked wins, placements, identities or leaderboard eligibility.
- Finalization updates the new counter within the existing atomic, exactly-once result transaction. Duplicate plays, reconnects and repeated finalization cannot add extra wins.
- `/auth/stats` adds `totalGames`, `totalWins`, `totalLosses`, `totalWinRate` and `unrankedWins`. Existing `games`, `wins` and `winRate` retain their ranked meaning for compatibility.
- Home, profile and sidebar personal records display the total fields. Ranked totals remain clearly labeled separately. Browser storage remains untrusted.
- Counts continue to survive after detailed history is retired; wins are not recalculated from a limited history page on every request. The backfill can recover only authoritative results that still exist. Older casual victories whose result rows were already removed cannot be invented; the reported recent results are retained.

## Mobile connection correction

- Centralized `GAME_PING_INTERVAL_MS=25000` and `GAME_PING_TIMEOUT_MS=20000` use Socket.IO's standard defaults. Valid ranges are 5000–30000 ms each. Heartbeats are less frequent, while temporary latency has more tolerance. A broken connection may consequently take longer to detect; the game's ten-second grace still begins after disconnect detection, and its cumulative grace/AI budgets remain unchanged.
- [Socket.IO documents the heartbeat behavior and defaults](https://socket.io/docs/v4/server-options/#pinginterval). The combined 45-second default is also below [Vercel's 120-second external rewrite timeout](https://vercel.com/docs/limits#proxied-request-timeout). Physical mobile suspension and provider behavior still require hosted playtests.
- An auth-owned connection lifecycle restores eligible sockets on page return, foreground visibility and network recovery, including `pageshow.persisted=false`. An explicit logout, sign-in screen or session revocation disables those recovery paths. Existing active reconnect attempts are not duplicated, and gameplay actions are not queued while disconnected.
- Clean page exits and offline events still close the socket/microphone promptly. No extra grace, redeal, timer reset or AI renewal is granted by a page event.
- Reports attach at most ten predefined connection reason codes. Emails label them **client-reported**. No network addresses, cookies, tokens, private cards or raw error text are attached. Server diagnostics count bounded disconnect reasons in memory using the existing sampling path.
- Automatic error reports now reuse the same-origin API configuration instead of falling back to localhost in a production build.

No production data was modified, no mail sent, and no game or account was created in production during this investigation.
