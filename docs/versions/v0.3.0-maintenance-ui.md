# v0.3.0 — Maintenance UI

Implemented 2026-11-26. Production deployment is separate from local verification.

Visitors now see a full-screen, mobile-friendly maintenance notice when the backend explicitly returns `maintenance: true` or `SERVER_MAINTENANCE`. The notice explains the temporary interruption, includes the BluffX logo/version, a manual Check again button and automatic recovery. Ordinary offline errors, cold starts and unavailable storage are not labeled maintenance.

The frontend checks the database-free `/health` once at startup and on transport failures, throttled to once per ten seconds. Authentication responses can also activate the notice. Only confirmed maintenance starts a 30-second health check; there is no recurring health polling for healthy visitors. Checks never request sessions, leaderboards or database readiness probes. Fetches time out, concurrent checks are suppressed, and timers/listeners are removed on unmount.

The game UI remains mounted but inert/hidden from assistive navigation beneath the notice. Focus moves to the maintenance heading. Existing resume credentials and account storage are not cleared. Once health explicitly reports normal operation and ready status, the page reloads to re-establish authentication and authoritative seat synchronization through existing startup logic. Recovery does not promise preservation of an uncommitted action or a previously expired seat.

The maintenance-only HTTP process now permits anonymous cross-origin status reads for direct local frontend/backend setups. Its responses contain no private information, load no database and continue rejecting auth/game traffic with HTTP 503. Production uses the existing same-origin Vercel `/health` rewrite. Vite's production preview mirrors that rewrite for verification.

## Rollout

No migration, credentials, environment variable or paid service is required. Publish the updated Vercel frontend to make the notice available; a browser that has never loaded this frontend revision cannot display code it does not yet have. Render continues using `node scripts/maintenance.js` during the handoff and `npm start` afterward, with health path `/health`. Deploy the latest main revision for the local cross-origin header improvement. Existing same-origin maintenance responses already carry the required status flag.
