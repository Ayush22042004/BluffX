# v0.3.0 audit fixes and playtest hardening

Date: 2026-11-13. Local implementation; not deployed. Package version remains 0.3.0. This follows the [development audit](../development-audit-2026-11-13.md); that document remains the historical pre-fix evidence.

## Implemented fixes

- Fixed the tutorial evidence portal being covered by its parent. Dialogs share an explicit layer scale; nested evidence is above its parent.
- The per-visit fullscreen recommendation remains visible and dismissible but no longer intercepts clicks through its informational area.
- Added shared focus management for every app dialog and nested tutorial evidence: initial focus, Tab wrapping, Escape, focus containment, restoration and listener cleanup. Busy settings/tutorial saves retain their close guards.
- Table settings now waits for the authoritative acknowledgement, prevents repeat saves, disables edits/closing while pending and preserves draft values with an inline error after rejection. Successful retries close the dialog normally.
- Shared auth/avatar/socket endpoints default to same-origin in production rather than localhost. Standard WebSocket upgrade attempts are enabled with polling fallback; `VITE_SOCKET_UPGRADE=false` is an operational opt-out. Same-origin routing and cookie/seat authentication remain intact. Actual hosted proxy support still needs post-deployment qualification.
- Added backend and Vercel security headers: nosniff, frame denial, referrer policy and a permissions policy allowing same-origin microphones. CSP starts report-only to qualify Google sign-in/fonts/voice before enforcement; this is not a claim of enforced CSP protection. Backend HSTS is sent only for secure production requests.
- Scheduler and retention failures increment sampled diagnostic counters. SQL query timings, pool occupancy and transport mix support diagnosis without recording statements, player identities or cards. Existing absolute-deadline scheduling, bounded pools and committed-before-acknowledgement rules remain unchanged.
- Converted lounge and portrait assets into WebP derivatives; original PNGs remain available as source artwork. Displayed asset sizes fell from 4,573,665 to 424,972 bytes (90.7% smaller). No generated/replaced artwork or portrait changes.
- Tutorial and social screens load on demand through local Suspense boundaries. Theme/dialog CSS is separated from the base stylesheet; obsolete preview overrides were removed. There is no whole-app rewrite or speculative game-engine replacement.
- Added staged ESLint checks for runtime/server scripts/frontend and CI integration. ESLint uses patched minimatch overrides, verified by lint and dependency audit. Client JSX unused-variable checking remains deferred; no TypeScript conversion is claimed.
- Builds emit public `version.json` containing only version/revision. Deployment checks optionally enforce matching frontend/backend versions with `DEPLOYMENT_EXPECTED_VERSION`. `npm run check:migrations` inventories applied/pending/checksum status in a read-only transaction and never applies migration SQL.
- Added a production-build browser harness on isolated 4020/5180 ports. It exercises same-origin auth, seat recovery, WebSocket upgrades and blocked-upgrade polling fallback without depending on development-module imports.

## Remaining external qualification

No software is certified fault-free. Physical headset/Bluetooth/mobile-background/different-network tests, hosted WebSocket proxy/Google login checks, a Render-to-Neon latency measurement, a backup restore rehearsal and hosted CI remain release tasks. SMTP/Resend is deliberately deferred at the user's request. The live backend was last observed at beta.1; local fixes do not change that deployment.

The earlier real-Neon latency sample was taken from the development machine. We added visibility and reduced frontend transfer/work; we did not claim to eliminate provider/network latency, bypass durability or change hosting regions. Render Free cold starts remain a platform constraint.

## Safe rollout

1. Review the local changes and run lint, audits, unit/PostgreSQL/browser/build checks. Run production-build checks as described below.
2. Verify the intended Neon database read-only with `npm run check:migrations`. Apply any pending reviewed migration through the existing explicit maintenance procedure, not through the inventory command.
3. Rehearse backup restore in an isolated database and select an invite-only unranked playtest. Preserve the single-owner maintenance handoff; do not run two independent authoritative instances.
4. Deploy matching backend/frontend revisions only after approval. No new backend secret is required for these fixes. The frontend defaults to its own origin; keep the documented Vercel rewrites pointed to the intended backend.
5. Run read-only checks with `DEPLOYMENT_EXPECTED_VERSION=0.3.0`; verify deployed security headers, Google login, WebSocket upgrade/fallback, fresh-seat reconnect and all three themes. Collect sampled commit/pool/transport metrics before tuning resources.
6. Qualify real voice across devices/networks and monitor existing provider usage limits. No SFU or paid infrastructure was added.
