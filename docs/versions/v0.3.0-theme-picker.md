# v0.3.0 player-selectable themes

Date: 2026-11-13. Local update; not deployed. Package version remains 0.3.0.

Settings now offers three accessible radio choices: Neon Blue (default), Neon Pink and Neon Emerald. Selection applies immediately across shared interface colors, scenery and logo treatment, and persists in the existing browser preference record. Preferences apply before React renders so saved themes also appear during account loading and login. Unknown saved themes fall back to blue; reduced motion remains independent. Blocked storage permits session-only changes.

Shared CSS tokens preserve color luminance/transparency across the three palettes. Player images, red card suits and semantic warning/error/presence colors retain their meaning. No whole-page filter affects content. Theme previews show all three palettes regardless of the current choice.

Changed: `Preferences.jsx`, `main.jsx`, `index.css`; added `theme-colors.css` and `client/tests/themes.spec.js`. No database changes, environment settings, dependencies or production deployment. Theme preference is browser-local, not synced across accounts/devices.

Verification: `npm run build` passed. `npm --prefix client run test:e2e -- themes.spec.js display-polish.spec.js` passed all four tests, covering immediate palette changes, refresh persistence, mobile fit, saved theme on the login page, invalid-value fallback with reduced motion enabled, beta labels and fullscreen guidance. Mobile theme-picker screenshot was visually inspected.
